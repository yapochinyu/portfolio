# HR-аналитика: удовлетворённость и риск увольнения

## Задача

Компания хочет предотвращать внезапные увольнения, особенно ключевых
специалистов. Две связанные задачи: (1) предсказать уровень удовлетворённости
сотрудника работой, чтобы не полагаться только на ручные опросники, и (2)
предсказать риск увольнения — используя удовлетворённость, предсказанную
моделью из первой задачи, как один из входных признаков.

**Метрики:** SMAPE (задача 1), ROC-AUC (задача 2).

## Данные

5 файлов: обучающая и тестовая выборки для каждой задачи. Тестовые признаки —
один и тот же файл для обеих задач (2000 сотрудников), обучающие выборки
задач не пересекаются. Данные предоставлены курсом и не публикуются.

## Что было сделано

- Приведение пропусков (в тесте часть пропусков закодирована пробелом, а не `NaN`) и опечаток в категориях к единому виду
- Пайплайн с кодированием (`OneHotEncoder`/`OrdinalEncoder`) и заполнением пропусков (`SimpleImputer`) внутри модели, без ручной точечной чистки
- **Явная проверка отсутствия пересечения `id`** между обучающими выборками задач 1 и 2 — только после неё предсказанная удовлетворённость честно используется как признак задачи 2, а не как утечка запомненного ответа
- Сравнение моделей для обеих задач с кросс-валидацией и подбором гиперпараметров
- Важность признаков — permutation importance по всей тестовой выборке
- Сравнение с Dummy-бейзлайном для обеих задач

## Результат

**Задача 1 (удовлетворённость):**

| Модель | CV SMAPE |
|---|---|
| Linear Regression | 25.0 |
| Decision Tree | 15.5 |
| **HistGradientBoosting** | **11.4** |

SMAPE на тесте: **10.9** (DummyRegressor — 37.6).

**Задача 2 (увольнение):**

| Модель | CV ROC-AUC |
|---|---|
| Logistic Regression | 0.918 |
| KNN | 0.924 |
| Decision Tree | 0.929 |
| SVC | 0.930 |
| **HistGradientBoosting** | **0.941** |

ROC-AUC на тесте: **0.930** (DummyClassifier — 0.50).

Сильнее всего на решение об увольнении влияют предсказанная удовлетворённость
и стаж. Портрет уволившегося сотрудника: короткий стаж, невысокая оценка
руководителя, зарплата почти вдвое ниже медианной (22800 против 34800).

**Вывод:** связка «предсказанная удовлетворённость → признак модели оттока»
методологически корректна (обучающие выборки задач не пересекаются по `id` —
проверено явно) и работает: обе модели значительно превосходят
Dummy-бейзлайн, а вторая задача получает содержательный признак вместо
ручного опроса.

## Что бы сделал иначе

Важность признаков в исходной версии проекта считалась SHAP-методом на одном
наблюдении и подавалась как общий вывод о влиянии признаков — заменил на
permutation importance по всей тестовой выборке, которая действительно
обобщается. Также в исходной версии не было явной проверки independence
обучающих выборок задач 1 и 2 перед переносом признака между ними — сама
конструкция была правильной, но это стоило доказать, а не предполагать.
